# 提示词变更必须同步《系统prompt汇总》

本项目的提示词散落在多处，且**同一条规则常常同时存在于 LLM 提示词和本地确定性代码里**。
只改一边会让文档失真、后续维护者踩坑，因此设定为强制规则。

## 什么算「提示词变更」

下列文件的下列内容发生增删改，**都算**，无一例外：

| 文件 | 需要同步的内容 |
|---|---|
| `lib/prompts/system-prompt.ts` | 人设正文、`describeCatalog()`、`describeConstraint()` |
| `lib/llm/index.ts` | 意图防呆正则（`BUY_PATTERN` / `REFUSE_PATTERN` / `ADJUST_PATTERN` / `INTRODUCE_PATTERN`）、偏好兜底抽取、乱码拦截、话术池、重试与温度策略 |
| `lib/memory/store.ts` | 记忆分层 / 状态语义、`decideMemoryAction` 规则顺序、`renderMemoryForPrompt` |
| `app/api/ai/route.ts` | 记忆意图正则、`factsFromMessage` 写入门槛、`pickTransition` 过渡语池、`renderMemoryReply` 模板 |
| `app/page.tsx` | `WELCOME` / `SCENES` / `QUICK` / 报错兜底文案 |
| `lib/llm/local-workflow.ts` | 选品链路的节点职责与过滤规则（决定模型嘴里能出现的商品） |

## 改之前先看文档

动手前先读根目录 **`系统prompt汇总.md`**，确认要改的规则在全链路里的所有落点——
「不吃辣」这类忌口规则通常同时存在于：
- 提示词正文的输出规范里
- `extractPrefsFromText` 的 `noSpicy` 正则里
- `local-workflow` 的硬过滤里

**改一边必须检查另一边。**

## 改完之后必须做

1. 更新 `系统prompt汇总.md` 的对应章节；
2. 在该文档末尾的「变更记录」表格追加一行（日期、改了什么、涉及文件）；
3. 跑 `npm run smoke`（需 dev server 已启动），确认 21 条回归用例没有退化；
4. 如果新增了行为，同时补一条 smoke 用例。

> 注意：smoke 的空状态文案里含有「我不吃辣」字样，
> 断言长期记忆是否被删除时**不能**拿 `reply` 做文本匹配，只能断言结构化快照 `data.memory`。

## 不要做的事

- 不要在 `docs/脆香零食-完整项目文档.md` 或 `cuixiang_prompt.md` 里改人设——
  它们是设计留档，已不是运行时真源，唯一真源是 `lib/prompts/system-prompt.ts`。
- 不要把具体商品清单写死进提示词，商品一律由 `lib/data/snacks.ts` 动态生成。

## 【快捷指令：继续】

当用户**单独**发送「继续」，或者在新会话的开头发送「继续」时，**立刻按顺序**读取以下三个文件：

1. `AGENTS.md`（了解架构规则）
2. `PROGRESS.md`（了解当前进度）
3. `docs/TEST_LOG.md`（了解最近的测试记录，**没有此文件则忽略**）

读完**不要做任何代码修改**，直接按这个格式汇报：

```text
当前项目进度 -> 最近修复的 Bug -> 下一步计划
```

汇报完固定问一句：**「接下来做哪个？」**

### 判断要不要触发：看「继续」后面有没有宾语

「继续」是个高频词，误触发的代价不小（每次都去翻三个文件，把正常对话拖成读档流程）：

| 用户说的 | 算不算 | 为什么 |
|---|---|---|
| `继续` / `继续吧`（单独一行，后面没宾语） | ✅ 触发 | 这就是在读档，没别的意思 |
| `继续推荐` / `继续写` / `继续改那个 bug` | ❌ 不触发 | 「继续」后面跟着**动作对象**，说的是业务，按当前任务正常执行 |
| `继续之前的开发` | ✅ 触发 | 说的是「上次那摊事」，不是某个具体动作（与 `AGENTS.md` 顶部【新会话启动规则】同口径） |

拿不准就按**不触发**处理，正常做当前任务——多问一句比先翻三个文件便宜。

### 与 `AGENTS.md` 顶部【新会话启动规则】的关系

两条规则读的是**同样三份文件**，区别只在触发方式：

| 规则 | 什么时候生效 | 谁发起 |
|---|---|---|
| `AGENTS.md`【新会话启动规则】 | **每个新会话自动生效** | 被动：会话一开就该读 |
| 本条【快捷指令：继续】 | 用户主动打出「继续」时 | 主动：用户中途想重新对齐进度 |

所以用户在会话中途发「继续」，不要当成「重复读一遍」，**直接给结论**——
汇报完进度、问一句要做什么，等他指方向再动手。
