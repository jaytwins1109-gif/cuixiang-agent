## 0. 怎么用

| 你要做的事 | 去哪 |
|---|---|
| 手动测完想记一笔 | 第 1 节，复制表格模板那一行往里填 |
| 想让日志自动变成记录 | 第 2 节：另开一个终端跑 `npm run capture-log`，边聊边自动追加 |
| 想按一次对话查全链路 | 拿 TraceID 去日志里 grep：`Select-String -Path dev-server.log -Pattern "\[a7f3k2\]"` |

日志打点格式与 TraceID 的生成规则见 [`lib/chat/trace.ts`](../lib/chat/trace.ts) 和
[`系统prompt汇总.md` 第 16 节](../系统prompt汇总.md#16-链路日志与测试归档2026-11-01-建立)。
**改打点格式必须连 `scripts/capture-log.mjs` 的正则一起改**，否则脚本捞不到行。

## 2. 自动归档（`scripts/capture-log.mjs` 追加）

用法：

```bash
# 终端 A：dev server 已经在跑
npm run dev

# 终端 B：监听日志，自动往本文件追加
npm run capture-log                          # 默认跟 dev-server.log
npm run capture-log -- --file dev-server.log # 换个日志文件
npm run capture-log -- --from-start          # 把文件里已有的日志也归档一遍
npm run capture-log -- --stdin               # 从管道读：npm run dev | npm run capture-log -- --stdin
npm run capture-log -- --out docs/备份.md    # 归档到别的文件（默认就是本文件）

# 用 npm run dev:log 起服务时，stdout / stderr 会分开落盘，两个都要跟：
npm run capture-log -- --file dev.out.log --file dev.err.log
```

然后正常在页面上聊天即可，**每一轮结束（收到 `[Response]`）就自动多一行**。

规则说明：

- 只捞带 `[TraceID]` 的行：四个打点（`Request` / `Brain` / `Local` / `Response`）用来拼一行，**服务端报错行**（`AI Route Error` / `Stream Error` / `Brain:provider` / `Degrade`）挂在那一轮的「备注」里，并让初筛变成 ⚠️
  ——它们原本只躺在 `dev.err.log` 里没人看，挂到表格上才叫可追溯
- 用 `npm run dev:log` 起服务时 stdout / stderr 分开落盘，**两个文件都要跟**，否则漏掉报错那一半
- 「是否通过」是**初筛**，不是结论：空文案、推荐意图却 0 卡片 → ❌；走了降级或本地拦截 → ⚠️；其余 → ✅
  ⚠️ 一律要人工复核——本地接管常常是对的（比如硬要忌口货被拦），脚本判不了对错
- 默认只处理脚本启动**之后**的新日志；加 `--from-start` 才处理已有内容
- Ctrl+C 退出时会把手上没凑齐的半轮也写进去，不会丢
